# 2026 赛季哨兵行为树优先级

这份文档用大白话说明当前行为树每一轮在做什么、先管什么、后管什么，以及底盘什么时候自转、什么时候允许微动。

## 每一轮的大顺序

比赛阶段内，行为树每一轮大致按这个顺序走：

1. 先加载参数和标定点，再刷新裁判系统、雷达、本车状态、队友状态等黑板数据。
2. 按设定频率把上一轮已经确定好的哨兵指令发出去。
   - 也就是进攻、防御、移动、确认复活这些状态。
   - 因为发送在本轮新判断之前，所以姿态变化可能慢一轮体现。
3. 先算“当前战略上应该去哪里”，但这一步还不直接发导航。
   - 这样底盘控制层不会拿旧目标或者默认 0,0 误判已经到点。
4. 再统一决定底盘和云台控制。
   - 底盘自转只从这一层发出去，避免不同分支互相抢控制权。
5. 最后进入战术分支。
   - 低血、死亡、遇敌这些全局门禁会先决定是否挡住后续战术。
   - 没被挡住时，再按补弹、基地威胁、普通目标点、默认姿态的顺序处理。

## 总体优先级

从高到低看，当前行为树的大优先级是：

1. 死亡和低血回血
   - 死亡时停云台扫描，底盘不自转，等待复活相关逻辑。
   - 血量低于低血线后进入回血锁存，去补给区回血。
   - 到达补给区以后默认防御姿态；如果 `energy_saving_mode_enable=true`，则切进攻姿态。
   - 只有血量回到安全线以后，回血锁存才释放。
2. 弹药补给
   - 弹药低时进入补弹逻辑。
   - 低弹判断默认使用 `rmuc_2026_params.yaml` 里的 `ammo_low`。
   - 只有补弹等待超时失败以后，才临时启用动态降级阈值：当前弹量的一半 -> 1 -> -1 放弃补弹。
   - 这个优先级高于基地威胁，也高于普通遇敌。
   - 补弹期间底盘不自转。
   - 前往补给区路上强制移动姿态。
   - 到达补给区以后默认防御姿态；如果 `energy_saving_mode_enable=true`，则切进攻姿态。
   - 等待补弹成功或超时降级。
3. 基地威胁回防
   - 基地掉血并且雷达发现敌人靠近基地时，进入基地威胁。
   - 这时优先去基地防御锚点。
   - 路上不自转；到了防御锚点以后才允许自转。
4. 语义区保护
   - 机器人进入配置的语义区后，禁用普通遇敌接管。
   - 在语义区内强制移动姿态，并禁止底盘自转。
   - 它低于基地威胁回防，高于普通遇敌。
   - 离开语义区后恢复正常遇敌和姿态决策。
5. 普通遇敌
   - 没有低血、补弹、基地威胁这些更高优先级任务时，普通遇敌会接管。
   - 它会取消当前导航，并让底盘原地自转。
   - `enemy_hold_attack_enable=true` 时切进攻姿态，`false` 时切防御姿态。
6. 普通目标点规划
   - 没有更高优先级任务时，按目标点逻辑走。
   - 目标点逻辑包括开局占前哨点、中央高地、梯形高地、堡垒区和巡逻点。
7. 默认姿态
   - 前面都没有接管时，到目标点就防御，没到目标点就移动。

## 普通目标点怎么选

普通目标点分两层：先选战略目标，再选真正发给导航的目标。

### 第一层：战略目标

战略目标由 `SelectObjective` 选：

1. 如果前哨站已经没了，或者 `conservative_mode_enable` 开启，战略目标直接按“前哨站已毁”处理。
   - 这时跳过开局占前哨点。
   - 也跳过前哨站存活时的中央高地逻辑。
   - 后面直接复用堡垒区、梯形高地和普通巡逻点那套逻辑。
   - `conservative_mode_enable` 只负责提前进入这套逻辑，不改变 `patrol_enable`、`destroyed_outpost_ladder_enable` 等开关自己的含义。
2. 比赛第一次进入阶段 4 时，内部启动一个开局占点计时器。
   - 计时器时间由 `cap_sustain_time` 管。
   - 这段时间内固定选择占领前哨点。
   - 计时结束以后，这条分支永久完成，不再回到占领前哨点。
   - 这个计时器用行为树内部时间，不再直接跟比赛已流逝时间绑定。
3. 开局占点结束后，如果己方前哨站还活着，战略目标是中央高地。
4. 如果己方前哨站已经没了，战略目标是梯形高地。

### 第二层：实际导航目标

实际导航目标由 `ObjectivePatrol` 决定：

1. 当前哨站还活着，战略目标是中央高地。
   - 如果 `out_alive_patrol_enable` 关闭，就只去中央高地。
   - 如果 `out_alive_patrol_enable` 开启，就在“中央高地 + out_alive_patrol_x 点位”之间循环。
   - 中央高地和这些存活巡逻点的停留时间都由 `patrol_hold_ms` 管。
2. 当前哨站已经没了，或者保守模式开启，战略目标是梯形高地。
   - 如果 `patrol_enable` 关闭，是否去梯形高地由 `destroyed_outpost_ladder_enable` 决定。
   - `destroyed_outpost_ladder_enable` 开启时，在梯形高地和堡垒区之间循环。
   - `destroyed_outpost_ladder_enable` 关闭时，只去堡垒区。
   - `patrol_enable` 只负责是否追加普通巡逻点，不负责开启梯形高地。
   - 梯形高地停留时间由 `ladder_time` 管。
   - 堡垒区停留时间由 `fortress_time` 管。
   - 普通巡逻点停留时间由 `patrol_hold_ms` 管。

所以，前哨站死亡后的规则是：

- `patrol_enable=false` 且 `destroyed_outpost_ladder_enable=false`：只守堡垒区。
- `patrol_enable=false` 且 `destroyed_outpost_ladder_enable=true`：梯形高地和堡垒区循环。
- `patrol_enable=true` 且 `destroyed_outpost_ladder_enable=false`：堡垒区和普通巡逻点循环，不经过梯形高地。
- `patrol_enable=true` 且 `destroyed_outpost_ladder_enable=true`：梯形高地、堡垒区和普通巡逻点一起循环。

## 导航目标怎么发

`ObjectivePlanner` 负责把当前实际目标发给 Nav2：

- 如果目标变了，会先取消当前 Nav2 目标，用来清掉旧目标缓存。
- 目标发布频率外层是 1 Hz。
- 同一个目标默认会去重，不会每 tick 疯狂重复发。
- 当前配置里 `max_dedup_ms=5000`，意思是：
  - 如果本次目标和上一次目标一样，5 秒以后允许重发一次。
  - 如果本次目标和上一次目标不一样，会立刻按新目标发布。
  - 如果取消导航清掉了缓存，也会允许下次重新发布同一个目标。

## 底盘自转优先级

底盘是否自转由统一控制层决定，从高到低是：

1. 已死亡
   - 停云台扫描。
   - 底盘不自转。
2. 正在低血回血流程里
   - 底盘不自转。
   - 优先回补给区回血。
3. 弹药太低，正在补弹
   - 底盘不自转。
4. 当前导航目标是补给区
   - 底盘不自转。
   - 回补给路上不因为普通敌情乱转。
5. 本车已经在补给区
   - 底盘不自转。
6. 基地威胁，并且已经到达防御锚点
   - 底盘自转。
   - 如果没有检测到敌人，并且 `move_around_enable` 开启，允许微动。
7. 基地威胁，但还没到防御锚点
   - 底盘不自转。
   - 先赶路回防。
8. 语义区内
   - 底盘不自转。
   - 普通遇敌功能被禁用。
9. 普通检测到敌人
   - 底盘自转。
   - 不允许微动。
   - 按 `enemy_hold_attack_enable` 请求进攻或防御姿态。
   - 这一条会在后面的敌情门禁里取消当前导航。
10. 已经到达当前导航目标
   - 底盘自转。
   - 如果 `move_around_enable` 开启，允许微动。
11. 其他情况
   - 底盘不自转。

一句话总结：回补给、补弹、回防路上不转；到点守点可以转；普通遇敌只自转不微动。

## 普通遇敌和基地威胁谁优先

基地威胁优先于普通遇敌。

如果只是普通看到敌人：

- 底盘自转。
- 不微动。
- 当前导航会被取消。
- `enemy_hold_attack_enable=true` 时切进攻姿态，`false` 时切防御姿态。
- 后续普通目标规划会被挡住。

如果同时处于基地威胁：

- 普通遇敌不取消回防导航。
- 先去基地防御锚点。
- 到了防御锚点以后再自转。

如果正在补弹或低血回血：

- 补弹和回血优先。
- 普通遇敌不会打断回补给。

## 姿态管理系统

哨兵姿态有三个值：

- `1`：进攻
- `2`：防御
- `3`：移动

当前 RMUC 行为树默认不主动请求 `1`。只有普通遇敌并且 `enemy_hold_attack_enable=true` 时，才会请求 `1`；开关关闭时，普通遇敌请求 `2`。

当前姿态不是在 `CommandHub` 里统一决策出来的，而是由各个战术分支用 `SelectPosture` 写入 `cmd.posture`。`CommandHub` 只负责最后加工和发布。

完整链路是：

```text
各战术分支 SelectPosture -> cmd.posture
CommandHub -> DecideRespawnCmd -> cmd.confirm_respawn
CommandHub -> PostureDegradationGuard -> cmd.final_posture
CommandHub -> SelectSentryCmdRate -> cmd.sentry_cmd_hz
CommandHub -> SentryCmdMux -> /sentry_cmd
```

当前发送频率是：存活时 `0.2 Hz`，死亡时 `1 Hz`。死亡时 `DecideRespawnCmd` 会把确认普通复活置为 `1`，存活时置为 `0`。

`SelectPosture` 自带 5 秒切换冷却：

- 如果请求的姿态和当前姿态一样，就继续保持。
- 如果请求切换姿态，并且距离上次切换已经超过 5 秒，就允许切换。
- 如果还在冷却中，就继续写回旧姿态。
- `cmd.allow_posture_send` 会被写出来，但当前没有接到 `SentryCmdMux`，真正起效的是“冷却中继续写旧姿态”。

`PostureDegradationGuard` 是最后一道保护：

- 同一个姿态累计超过 180 秒，会短暂强制切到另一个姿态。
- 防御姿态超时后，强制切移动 5 秒。
- 进攻或移动姿态超时后，强制切防御 5 秒。
- 强制时间结束后，再恢复当前战术分支想要的姿态。
- 但死亡、低血、补弹、基地威胁这些更高优先级状态会跳过降级；如果已经处在强制切换中，也会立刻取消强制姿态。
- 语义区也在这里做最后接管：人在语义区里时强制移动姿态，离开语义区以后恢复正常姿态优先级。

## 姿态优先级

因为行为树是按顺序 tick 的，姿态优先级跟战术分支接管顺序一致。大致从高到低是：

1. 死亡和低血回血
   - `LowHPRetreat` 会请求移动姿态。
   - 目的就是尽快回补给区或者等待复活流程。
2. 补弹
   - 补弹分支会压过基地威胁和普通遇敌。
   - 前往补给区路上请求移动姿态。
   - 到达补给区以后请求防御姿态。
3. 基地威胁
   - 到达防御锚点并且检测到敌人时，请求防御姿态。
   - 没到锚点，或者到了但没有检测到敌人时，请求移动姿态。
4. 语义区强制移动
   - 进入语义区以后，最终发布姿态强制改成移动。
   - 这一条低于基地威胁，高于姿态降级保护。
   - 离开语义区以后，不锁存，继续按正常姿态优先级走。
   - 当前语义区使用 `semantic_zones_file` 里的区域，并按 `semantic_ignore_enemy_zone_type` 指定的类型判断。
5. 姿态降级保护
   - 低于基地威胁、补弹、低血和死亡。
   - 高于普通遇敌、普通目标点和默认姿态。
   - 它只是在某个姿态持续太久时，临时切走几秒。
6. 普通遇敌
   - `EnemyHold` 会按 `enemy_hold_attack_enable` 请求进攻或防御姿态。
   - 它只取消当前导航，让底盘原地自转对敌。
7. 普通目标点规划
   - 到达当前目标点时，请求防御姿态。
   - 还在导航路上时，请求移动姿态。
8. 默认姿态
   - 前面的分支都没有接管时，到点防御，没到点移动。

注意：`CommandHub` 在每一轮比较靠前的位置发布，所以 `/sentry_cmd` 上看到的姿态可能是上一轮战术刚写好的结果。这个慢一轮是当前结构的正常现象。

## 微动什么时候生效

微动由 `move_around_enable` 统一开关控制。

当前会触发微动的场景只有两个：

- 基地威胁时，已经到达防御锚点，并且当前没有检测到敌人。
- 已经到达当前导航目标。

普通遇敌时不微动，只自转。

微动本身不阻塞主行为树，它只是额外发布附近随机目标，让机器人在允许的守点状态下小范围移动。

## 低血回补给次数监控

行为树里有一个低血回血锁存监控。

- 当血量第一次从正常状态跌到低血线以下时，低血回补给次数加 1。
- 血量没有回到安全线之前，不会重复加次数。
- 因为弹药低而回补给不计入这个次数。
- 当前实现只看血量锁存跳变，没有额外接入死亡状态；如果本来不在回血锁存里，血量直接变成 0，也会按一次低血触发计数。
- 监控日志大约 1 分钟打印一次。

日志里能看到类似：

```text
[UpdateHealRecoveryLatch] low HP supply retreat monitor: count=... active=... hp=... low=... safe=...
```

## 对外发出的东西

行为树最终主要对外发三类东西：

- 底盘和云台控制。
  - 看 `/red_standard_robot1/robot_control`。
  - 重点看 `chassis_spin`。
- 导航目标。
  - 看 `/red_standard_robot1/goal_pose`。
  - 重点看当前目标是不是期望的点位。
- 哨兵姿态指令。
  - 看 `/red_standard_robot1/sentry_cmd`。
  - 重点看进攻、防御、移动和确认复活。
