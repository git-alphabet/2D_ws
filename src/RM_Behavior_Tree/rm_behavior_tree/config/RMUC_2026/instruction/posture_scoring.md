# 姿态评分系统 (DecidePosture)

> 代码位置: `plugins/rmuc_2026/action/decide_posture.cpp`
> 节点名称: `DecidePosture`
> 调用位置: `CommandHub.xml` → `SentryCmdMux` → `/sentry_cmd`

## 姿态类型

| 姿态值 | 名称 | 效果 |
|--------|------|------|
| 1 | 进攻 | 攻击力↑ 防御力↓ |
| 2 | 防御 | 防御力↑ 攻击力↓ |
| 3 | 移动 | 移动速度↑ |

## 评分表

每个 tick 三姿态同时算分，**最高分胜出**（平局优先：防御 > 移动 > 攻击）。

| 条件 | 含义 | 谁加分 | 为什么 |
|------|------|--------|--------|
| **基础分** | 没有任何条件时的默认倾向 | 移动(10) > 防御(8) > 攻击(5) | 默认倾向移动，避免傻站 |
| **has_target** | `robot_status.detect_enemy` 电控检测到敌人 | 攻击 +35 | 看到敌人当然要打 |
| **hp > 50%** | 当前血量超过上限一半 | 攻击 +20 | 血量健康，可以激进输出 |
| **30% < hp < 50%** | 血量中低区间 | 攻击+8, 防御+15, 移动+5 | 血量不太舒服，偏向防御，攻击和移动也有点加分 |
| **hp < 30%** | 血量危急 | 防御 +35 | 快没了，必须防御续命 |
| **buff_defense > 0** | 裁判系统给了 **防御增益** buff（占领增益点获得） | 攻击 +15 | 有防御 buff 护体，可以更大胆地输出 |
| **buff_cool > 0** | 裁判系统给了 **冷却增益** buff（枪管冷却加快） | 攻击 +12 | 冷却快 = DPS 高，适合进攻 |
| **buff_vuln > 0** | 己方被标记了 **易伤** debuff（被打伤害更高） | 防御 +50 | 被易伤了还攻击就是送，赶紧防御 |
| **base_threat** | 基地受到威胁（基地血量下降被检测到） | 防御 +30 | 基地危险要保护。(`base_threat=true` 时实际代码直接强制进攻姿态，这个+30是评分系统里的，但会被代码覆盖) |
| **heat > heat_high** | 枪管热量超过阈值（默认210） | 防御 +25 | 枪管过热打不了了，切防御减少受伤 |
| **!has_target** | 没检测到敌人 | 防御+8, 移动+10 | 没人打就别进攻了，巡逻或防御 |
| **elapsed > 180s** | 比赛过了 3 分钟（后半场） | 攻击 +18 | 后半场要抢发弹量配额，需要更激进 |
| **ammo <= 0** | 允许发弹量为 0（没子弹了） | 攻击→0, 移动+50 | 没弹药攻击直接归零，移动评分拉满赶紧跑 |

## 特殊规则

- **5秒冷却**: 切换姿态后 5 秒内不能再切，防止频繁抖动
- **12分阈值**: 新姿态评分必须比当前姿态高 ≥12 分才会切换，避免小幅波动导致来回切
- **base_threat 强制覆盖**: 如果 `base_threat=true`，评分系统直接跳过，**强制切攻击姿态**且无视 5 秒冷却 — 基地危险时什么都不管直接开打

## 数据流

```
裁判系统 → sentry_decision_status → ParseSentryBlackboard → DecidePosture → SentryCmdMux → /sentry_cmd
                                         ↓
                                    current_posture (反馈)
                                    hp_cur, hp_max
                                    heat_cur
                                    has_target
                                    base_threat
                                    buff_*
                                    ammo_allow

```

## 代码逻辑详解

### 整体结构

```
tick() 一共做 4 件事:
1. 读取输入 → 2. 三姿态评分 → 3. 特殊覆盖 → 4. 防抖过滤 → 输出
```

### 第一步: 读取输入 (38-55行)

从黑板读取 13 个输入, 都有默认值兜底:
```
hp=400, hp_max=400, heat=0, heat_high=210, elapsed=0
has_target=false, base_threat=false, current_posture=3
buff_cool=0, buff_defense=0, buff_vuln=0, ammo=300, now_ms=0
```
然后算 `hp_ratio = hp / hp_max`（0.0~1.0）

### 第二步: 三姿态评分 (59-88行)

**攻击评分** (基础5分):
```
+35  看到敌人
+20  血量>50%  |  +8 血量30%~50%
+15  有防御buff  |  +12 有冷却buff
+18  过了3分钟(后半场)
→0   没弹药时归零
```

**防御评分** (基础8分):
```
+50  易伤debuff
+30  基地受威胁
+35  血量<30%  |  +15 血量30%~50%
+25  热量超限
+8   没有敌人
```

**移动评分** (基础10分):
```
+50  没弹药
+10  没有敌人
+5   血量30%~50%
```

### 第三步: 选出最高分 (91-99行)

```cpp
// 平局优先顺序: 防御 > 移动 > 攻击
int posture = 3;             // 先假设移动
if (score_defense >= max_score) posture = 2;  // 防御 >= 移动就选防御
if (score_attack > max_score)  posture = 1;   // 攻击严格大于才选攻击
```

**注意**: 防御用 `>=` (平局赢移动), 攻击用 `>` (必须严格高于)。设计意图: 宁可多防不乱攻。

### 第四步: 特殊覆盖 + 防抖 (101-138行)

#### 4a. 初始化 (101-107行)
```
stable_posture = 裁判系统反馈的当前姿态（1~3有效才用，否则用上次记录的）
首次运行时记录初始姿态和时间戳
```

#### 4b. base_threat 强制覆盖 (109-114行)
```
如果基地受威胁 → 强制进攻(1), 无视评分/冷却, 直接返回
同时设 crisis_override_active_ = true
```

#### 4c. 危机恢复 (116-121行)
```
如果上一次是危机覆盖, 这次不是了 → 重置冷却计时器
(让危机结束后能立刻切换到评分结果, 不被冷却卡住)
```

#### 4d. 防抖过滤 (123-138行)
```
current_score = 当前实际姿态的评分
desired_score = 评分系统选出的新姿态评分

如果新姿态 ≠ 当前姿态:
  拒绝切换条件 (任一满足就不切):
    1. cooldown_active: 距上次切换 < 5秒
    2. !switch_has_margin: 新评分 < 当前评分 + 12

  允许切换时:
    记录新姿态 + 重置计时器

如果新姿态 = 当前姿态:
    记录当前姿态(保持)
```

### 举个例子

假设: hp=200/400(50%), has_target=true, buff_cool=30, elapsed=200s, ammo=150
```
攻击: 5 + 35(目标) + 20(hp>50%) + 12(冷却buff) + 18(后半场) = 90
防御: 8
移动: 10

→ 评分选攻击(90分)

如果当前是防御(8分):
  desired(90) >= current(8) + 12? → 90>=20 ✓
  冷却过了? → 假设过了 ✓
  → 切换到攻击!
```

总结：这是一个 **评分 + 滞回 + 冷却 + 危机覆盖** 四层过滤的姿态决策系统。
