自主导航技术路线
一、整体架构

自主导航部分采用分层架构，依次为传感器前端、点云融合、地形分析、Nav2、SLAM、速度输出。


二、点云融合（核心）

2.1 设计思路

机器人搭载两台特性互补的激光雷达：

  传感器              角色              视场              优势
  odin1              主定位 + 建图       120°H × 90°   高频率、高精度里程计，视觉激光惯性融合
  Livox mid360       副雷达补盲        非重复扫描 360°   360度视野，细节丰富，弥补 odin1 盲区

关键设计决策：不做位姿融合。odin1 始终是唯一的里程计/定位源。mid360 仅用于点云增补——将其点云变换到 odin1 的 odom 坐标系后，在地形分析之前完成融合。


2.2 融合节点

算法流程：

  1. 订阅两路 PointCloud2：
      主输入：odin1 的点云（odom 坐标系）
      副输入：mid360 经坐标变换后的点云（odom 坐标系）
  2. 时间同步：ApproximateTime，80ms 容差
  3. 可选的基于 TF 的时间补偿（对齐副雷达时间戳到主雷达时钟）
  4. 拼接两路点云，输出融合点云
  5. 降级策略：mid360 不可用时，直接透传主雷达点云



2.3 各传感器处理链路

odin1 路径（主）：驱动输出处理后的点云和高频里程计，经扫描生成模块转换为 2D 扫描供 SLAM 使用；同时驱动内置 SLAM 直接输出配准点云，送入融合节点作为主输入。

mid360 路径（副）：驱动输出 livox 点云和 IMU 数据，经点云里程计生成配准点云，再经坐标变换接口变换到 odom 坐标系，送入融合节点作为副输入。

坐标变换接口使用 odin1 的里程计作为统一参考，将 mid360 点云变换到 odin1 的 odom 坐标系。


2.4 融合同步策略

主雷达（odin1）和副雷达（mid360）的点云通过 ApproximateTime 进行时间同步，容差 80ms，拼接后输出融合点云。同时支持基于 TF 的时间补偿，将副雷达时间戳对齐到主雷达时钟。

80ms 容差用于补偿 odin1 板载 SLAM 与 mid360 侧 CPU 处理之间的延迟差异。TF 补偿修正两个传感器域之间的时钟漂移。


三、地形分析与 3D 代价地图

3.1 双尺度地形分析

融合后的点云同时送入两个并行的地形分析节点：

  节点          尺度            体素大小    半径    输出            用途
  局部分析      局部（近场）    0.05m       5m      局部地形图      局部代价地图：精确的近距障碍物
  全局分析      全局（远场）    0.1m        10m     全局地形图      全局代价地图 + 障碍物扫描生成

两个节点均源自地形分析算法。通过分位数排序估计地面高度，将相对地面高度编码为 PointCloud2 的 intensity 字段。低于阈值的点视为可通行区域，高于阈值的点视为障碍物。


3.2 自定义 3D 代价地图层

自定义 Nav2 代价地图层，消费地形分析输出的 PointCloud2 消息。使用 intensity（相对地面高度）作为障碍物度量：

   min_obstacle_intensity: 0.1 —— 过滤地面噪声
   超过阈值的体素标记为障碍物代价值
   同时集成到 local_costmap 和 global_costmap

代价地图配置：

    local_costmap:  滚动 5×5m,   0.05m 分辨率
    global_costmap: 滚动 20×20m, 0.05m 分辨率
    插件: static_layer(禁用) + intensity_voxel_layer + inflation_layer(0.6m)


3.3 障碍物扫描生成链路

为控制器（尤其是 NeuPAN）额外生成 2D 激光扫描。全局地形图经点云转激光扫描模块转换为主雷达扫描；在双雷达模式下，主副雷达扫描经扫描合并模块合并为最终障碍物扫描，送入 controller_server。

扫描合并模块基于视场优先级合并两路 LaserScan：主雷达在其视场内优先，视场外取两者的最小值。


四、NeuPAN 控制器（神经网络路径跟踪）

4.1 架构概览

NeuPAN（Neural Proximal Alternating-minimization Network）是一种学习型控制器，替代传统 PID 追踪。注册为 Nav2 的 FollowPath 插件。

论文：IEEE Transactions on Robotics, 2025 (Ruihua Han et al.)


4.2 集成架构

NeuPAN 采用 C++ 插件 + Python HTTP 服务 的架构。C++ 插件注册在 Nav2 controller_server 中，内部包含四个模块：障碍物提取器读取代价地图栅格，路径处理器将 Nav2 全局路径转换为 NeuPAN 航点，Python 桥接器通过 HTTP POST 调用 Python 服务（默认 http://127.0.0.1:18080/forward），可视化模块发布调试路径和标记。Python 服务作为独立进程运行，内部包含 DUNE（神经网络障碍物编码器）和 NRMP（凸优化求解器）。

C++ 侧负责 Nav2 生命周期、代价地图访问和 TF。Python 侧负责神经网络推理和优化求解。通信方式为 JSON/HTTP，超时 500ms。


4.3 神经网络模型：PAN（近端交替最小化网络）

PAN 在两个子网络之间迭代交替：

Step 1  DUNE（深度展开神经编码器）：

   输入：障碍物点 (x, y)，机器人中心坐标系
   网络结构：多层全连接网络，输入维度 2，隐藏层 32 维，输出维度 4（机器人边数），含 LayerNorm 和 Tanh/ReLU 激活
   输出：mu（每个机器人边一个值，矩形机器人通常为 4）
   推导 lambda = R @ G^T @ mu 用于距离计算
   按距离排序，最近障碍物优先处理

Step 2  NRMP（神经正则化运动规划器）：

   通过 cvxpylayers（可微分 CVXPY）构建凸优化问题
   优化变量：状态轨迹 s (3×T+1)、控制序列 u (2×T)、距离松弛变量 dis (1×T)
   代价函数 = 航迹跟踪 + 避障（L1 正则化）+ 近端收敛
   约束：线性化动力学、速度/加速度边界、距离边界
   求解器：ECOS

迭代：PAN 运行 iter_num=2 次，当 mu/lambda 变化量 < iter_threshold=0.1 时收敛。


4.4 详细数据流

每次控制周期调用时：(1) 从代价地图提取所有高于膨胀障碍物阈值的障碍物点集；(2) 从 TF 获取当前机器人状态 [x, y, theta]；(3) 将障碍物点和机器人状态通过 HTTP POST 发送到 Python 服务，Python 侧下采样后执行 PAN 迭代（DUNE 编码、NRMP 求解、输出最优控制动作）；(4) 根据运动学类型解码动作——全向输出 vx/vy，差速输出线速度/角速度，阿克曼输出速度和转向角；(5) 发布速度指令。


4.5 插件切换

控制器在启动时通过配置文件选择：

  模式          插件类型
  经典 PID      全向 PID 追踪控制器（默认）
  神经网络      NeuPAN 控制器

选择 NeuPAN 时，启动代码自动加载专用配置，强制启用障碍物扫描相关模块，并可通过配置覆盖 bt_navigator、代价地图、behavior_server 的机器人坐标系。


五、导航模式

5.1 模式概览

系统支持三种导航模式，区别在于目标来源和决策自主性：

  模式      目标来源              决策层                                    控制器
  全自动    行为树内部逻辑        订阅外部状态，自主生成目标                pid/neupan
  半自动    外部 goal_pose 话题   人工发送目标坐标，Nav2 负责规划+执行      pid/neupan
  手动      遥控指令              操作员直接控制底盘运动                    无（直接下发速度指令）

全自动和半自动模式共享同一套 Nav2 规划/控制栈（planner_server + controller_server + bt_navigator），区别在于谁决定去哪里。手动模式绕过 Nav2，由操作员直接下发速度指令控制底盘。


5.2 全自动模式

行为树作为高层决策器，订阅外部状态话题（如系统状态、环境传感器），基于优先级逻辑自主生成导航目标。优先级从高到低依次为：紧急响应（撤退、安全）、资源管理（补给、充电）、防御行为（巡逻、警戒）、任务执行（任务航点）、默认姿态（空闲位置）。行为树通过 SendGoal 节点发布 PoseStamped 到 goal_pose 话题，bt_navigator 订阅该话题并通过 navigate_to_pose 行为树执行。

具体的优先级逻辑和状态订阅由加载的行为树 XML 定义——导航栈本身与决策策略解耦。


5.3 半自动模式

外部操作员或决策节点向 goal_pose 话题发布 geometry_msgs/PoseStamped。Nav2 栈全权负责路径规划、避障和执行。bt_navigator 接收目标后，通过 navigate_to_pose 行为树调用 ComputePathToPose（ThetaStar 规划器）生成路径，再由 FollowPath（pid_pursuit 或 NeuPAN）跟踪执行。

这是最简单的集成点——任何能发布 PoseStamped 的节点都可以指挥机器人。无需定制行为树；默认的导航行为树自动处理重规划和恢复。

多航点：NavigateThroughPoses action server 接受航点列表。外部节点可通过 navigate_through_poses action 接口发送批量目标，或向 waypoints 话题发布 visualization_msgs/MarkerArray 供 BT 节点收集。


5.4 模式选择

模式在启动时通过配置文件中的导航开关参数选择：

  controller_plugin: PID 追踪控制器或 NeuPAN 控制器
  behavior_tree: 指定决策行为树路径（全自动），半自动模式需要人工发送goal指令

启动代码解析所有标志并写入各 Nav2 节点的最终参数。不支持运行时切换——需要重新启动。


5.5 Nav2 底层行为树

所有模式共用同一套 Nav2 层的行为树执行实际的规划/跟踪循环：

单目标导航：NavigateRecovery 包含 6 次重试，内层 PipelineSequence 以 1Hz 频率调用 ComputePathToPose（ThetaStar 规划器）并由 FollowPath 跟踪；恢复阶段依次执行 Spin(90°) 和 BackUp(0.15m)。

多航点导航：结构类似，区别在于规划阶段先通过 RemovePassedGoals 清除已到达的航点，再调用 ComputePathThroughPoses 生成连续路径。

关键设计选择：

   不使用 ClearEntireCostmap 节点：BtServiceNode 在 XML 加载阶段同步等待服务；若代价地图尚未激活，会抛异常导致整条 lifecycle 链终止。改用 Spin + BackUp 恢复策略。
   1Hz 重规划频率：每秒重新计算路径，平衡响应性与计算负载。
   6 次重试预算：提供足够的恢复尝试次数。


六、速度输出管线

controller_server 输出的速度指令经 velocity_smoother 平滑处理（20Hz，最大 [2.5, 2.5, 3.0] m/s），再经速度变换模块适配后输出到底盘。速度变换模块同时输出自旋指令用于底盘 yaw 自旋。

速度变换模块处理 Nav2 内部坐标系与外部底盘坐标系之间的适配。同时执行减速区限速（语义区域）和非线性自旋行为。


七、生命周期管理

所有 Nav2 节点由 lifecycle_manager_navigation 统一管理：

   bond_timeout: 12.0s
   respawn: 启用（节点崩溃后自动重连）
   启动延迟: 启动后 12s（等待 odin 驱动初始化完成）

管理的节点：controller_server, smoother_server, planner_server, behavior_server, bt_navigator, waypoint_follower, velocity_smoother。
